# (주)디엔엠 연차·근로자명부 관리 v8.2

기존 v8.1(Netlify Functions + Netlify Blobs)을 기반으로 한 전체 교체용 배포 소스입니다. SB선보 챗봇 프로젝트가 아니라 **디엔엠 연차관리 GitHub 저장소**에 적용하세요.

## 이번 버전의 변경

- 신청 구분 네 개를 한 줄로 배치: 하루 / 기간 · 오전 반차 · 오후 반차 · ⏱ 시간단위.
- 실제 DNM 로고를 로그인·상단·favicon에 반영.
- `근로자명부` 페이지에서 직원정보 및 관리자/결재자/로그인 허용을 독립 지정.
- 이름, 사원코드, 부서, 직책, 입사일, 연차기준일, 퇴사일, 연락처, 주소, 경력, 비고를 관리.
- 원본과 운영정보 비교, Excel 미리보기 후 선택 반영, 원문 이력 및 변경 감사기록.
- 1일=8시간, 30분=0.5시간. 내부 원장은 정수 분 단위이며 화면·Excel은 정수 일수와 남은 시간으로 분해.
- 매 입사기념일, 이전 잔여를 이월하지 않고 새 주기 발생량으로 시작. 과거 신청·결재·소멸 이력은 보존.
- 한 명 결재라인 및 다단계 결재 지원. 선택한 마지막 결재자가 최종 승인자.
- 과거 사용내역 Excel 이관, JSON 백업/복원 유지.

## 직원명부 원본 반영 기준

첨부 `근로자명부2026.xlsx`의 `2026` 시트를 기반으로 작성했습니다. 원본 표제 기준일은 **2026년 07월20일 현재**입니다. 파일명의 2026을 현재 재직상태 확인일로 해석하지 않았습니다.

| 구분 | 수 | 처리 |
|---|---:|---|
| 현재 직원 명부 | 47명 | 신규 설치 시 직원 계정 자료로 사용 |
| 퇴직자 기록 | 57행 | 참고 원문 이력, 계정 생성 안 함 |
| 과거 입사자 기록 | 50행 | 중복을 포함한 참고 원문 이력, 계정 생성 안 함 |
| 시스템 관리자 | 별도 1계정 | 직원 인원수에서 제외 |

기존 사이트에서는 기존 직원 ID·로그인·비밀번호·권한·신청이력을 유지합니다. 새 명부의 입사일·직책 등 운영정보는 **근로자명부 → 첨부 명부 비교 → 선택 항목 반영**에서 확인 후 적용하세요. 권한 및 비밀번호는 명부 업로드로 덮어쓰지 않습니다. 기존 연차 산정 기준일도 보존합니다. 재입사·촉탁 등 기준일 변경이 필요하면 직원 수정에서 별도 확인합니다.

직책란과 비고의 승진 내용, 퇴사일/입사일과 비고가 다른 경우 원문을 보존하고 검토합니다. 비고를 보고 새로운 직책·퇴사일·근속 기준을 임의 추론하지 않습니다. 주민등록번호는 서버 직원자료·공개 파일·명부 내보내기에 포함하지 않습니다. 연락처·주소·경력·명부 이력은 관리자 전용 API에서만 제공합니다.

## 관리자와 결재자는 다릅니다

근로자명부 → 직원 행의 **정보·권한** → 체크박스 → 저장.

- **관리자 지정**: 직원명부, 권한, 전체 연차현황, Excel, 백업, 근무기준 관리.
- **결재자 지정**: 직원이 결재라인에서 선택할 수 있는 사람.
- 두 항목을 함께 선택하거나 별도로 지정할 수 있습니다. 관리자라고 모든 신청을 대신 승인할 수 있는 것은 아닙니다. 지정된 순서의 결재자만 승인합니다.
- 대표이사 김정배 직원 계정은 관리자 권한을 유지합니다. 대표자를 모든 신청의 최종 승인자로 강제 고정하지 않습니다.
- 퇴사자는 로그인 중지 처리하며 기존 신청·결재 기록은 유지합니다.

## 사용량 예시

| 상황 | 일수 | 나머지 시간 |
|---|---:|---:|
| 30분 사용 | 0 | 0.5 |
| 오전/오후 반차 | 0 | 4 |
| 하루 사용 | 1 | 0 |
| 15일 중 0.5시간 사용 후 잔여 | 14 | 7.5 |
| 15일 중 1일 4.5시간 사용 후 잔여 | 13 | 3.5 |

시간 값은 하루를 초과하는 총시간이 아니라 **정수 일수를 제외한 나머지 시간**입니다. 총시간은 신청내역 보조 표시 및 Excel 별도 열에서 확인할 수 있습니다. 초과사용은 음수 잔액 대신 ‘초과 N일 H시간’으로 표시합니다. 기존 방침대로 잔여 부족 신청은 허용합니다.

## 입사일 기준 소멸·재발생

2024-10-16 입사자의 예:

- 2025-10-16 ~ 2026-10-15: 해당 주기 발생량에서 그 주기에 귀속된 승인 사용량을 차감.
- 2026-10-16: 이전 미사용분의 새 주기 이월은 0. 새 주기의 발생량으로 계산.
- 과거 주기의 잔여는 연차대장 ‘소멸 대상 잔여’에 보존. 신청과 결재 기록을 삭제하는 초기화가 아님.
- 주년을 걸친 기간/시간 신청은 실제 사용 날짜별 분 단위로 나누어 해당 주기에 귀속.

별도 예약 작업 없이 **조회·신청·승인 시 한국시간 날짜에 맞춰 주기를 계산**합니다. 자정에 과거 데이터를 지우는 구조가 아닙니다. 화면을 오래 열어두었으면 새로고침하여 현재 날짜 기준으로 조회하세요.

기본 발생 계산은 1년 미만 월 개근 1일(최대11일), 1년 이상 15일, 계속근로3년부터 2년마다1일 가산(최대25일)을 가정합니다. **명부에는 출근율·개근 실적이 없으므로 실제 적격 여부를 확정할 수 없습니다.** 관리자가 연차대장 → 발생량 확인·수정에서 해당 주기 발생량을 확인/보정할 수 있습니다.

휴가 사용가능 잔액 소멸과 미사용수당 지급 의무는 별개입니다. 사용촉진 절차, 사용자 귀책, 휴직·촉탁·재입사, 출근율은 노무 검토가 필요합니다. 프로그램은 미사용수당 면제 여부를 자동 판정하지 않습니다.

## 기존 자료의 날짜별 차감

v8.1의 시간 신청은 hourly_segments, 하루 신청은 charge_dates를 이용해 그대로 분 단위로 변환합니다. 날짜별 근거가 없는 과거 ‘연도합계’ 또는 불명확한 이관자료는 총량을 임의 분배하지 않고 시작일에 귀속하며, **이관 주의사항**을 표시합니다. 관리자 확인 후 가감조정 또는 날짜별 이관으로 정리하세요. 새 신청은 30분 단위지만 기존 자료에 다른 단위가 있으면 임의 반올림으로 소실시키지 않고 보존합니다.

## 저장·배포 구조

GitHub는 코드 버전관리, Netlify는 화면·Functions 운영, Netlify Blobs는 운영 자료를 저장합니다.

- 공개 파일: `public/index.html`, `app.js`, `style.css`, logo 등.
- 서버 API: `netlify/functions/api.mjs`.
- 운영 store: `leave-manager-data` / `state` (이름 변경 없음).
- 로그인/미리보기 store: `leave-manager-sessions`.
- ETag 조건부 저장으로 동시 수정 충돌을 409로 알립니다. 충돌 시 새로고침 후 다시 처리합니다.

이 프로젝트는 index.html 더블클릭만으로 운영할 수 있는 정적 시연본이 아닙니다. GitHub 연동 Netlify 배포에서 Functions를 함께 실행하세요. `publish = public`을 유지해야 직원 초기자료가 정적 파일로 공개되지 않습니다.

기존 계정 비밀번호는 변경하지 않습니다. **새 설치**의 별도 관리자는 admin / 0996, 직원은 기존 직원명 로그인과 초기1111입니다. 실제 운영 전에 모두 각자의 강한 비밀번호로 변경하세요. 공개 로그인 화면에는 기본 계정을 안내하지 않습니다. GitHub는 Private으로 관리하고 원본 주민등록번호 포함 Excel을 저장소에 넣지 마세요. 백업 JSON에는 계정 해시와 개인정보가 있으므로 접근을 제한해 보관하세요.
